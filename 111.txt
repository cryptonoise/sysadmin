### ASSISTANT
Причина: **Nginx перехватывает или блокирует трафик Reality**, потому что VLESS+Reality — это *не HTTP-трафик*, а замаскированный TLS-хендшейк, который Nginx не может корректно проксировать как обычный веб-запрос.

Когда ты ставишь Nginx перед 3x-ui (особенно если пытаешься делать reverse proxy на порт Xray), происходит следующее:
1.  Nginx принимает TCP-соединение.
2.  Пытается прочитать HTTP-заголовок или TLS SNI для маршрутизации.
3.  Reality-клиент (Happ) шлёт специфический ClientHello, который Nginx либо не понимает, либо считает невалидным HTTP/HTTPS запросом.
4.  Nginx сбрасывает соединение или отдаёт свою заглушку/сертификат вместо того, чтобы прозрачно передать байты в Xray.
5.  Связка устанавливается (поэтому "подключение работает"), но данные не текут ("интернета нет").

### Как пофиксить

**Вариант А (Рекомендуемый): Убрать Nginx из цепочки Reality**
Reality **не нужен** Nginx. Он сам маскируется под целевой сайт (у тебя `amd.com`). Nginx тут только мешает.
1.  В 3x-ui настрой inbound VLESS+Reality слушать напрямую на порту 443 (или любом другом).
2.  Останови Nginx или убери его с этого порта.
3.  Если тебе нужен Nginx для обычного сайта, повесь его на *другой* порт (например, 8443) или используй разные IP.

**Вариант Б: Разделение портов (если Nginx обязателен)**
Если Nginx должен оставаться на 443 для сайта:
1.  Перенеси inbound Reality в 3x-ui на другой порт (например, `26009` как в твоем конфиге xhttp, или любой свободный).
2.  В Happ укажи этот новый порт.
3.  **НЕ** пытайся проксировать этот порт через Nginx (`proxy_pass`). Пусть клиент подключается к нему напрямую.

**Вариант В: Stream Proxy (только если очень нужно за Nginx)**
Если ты *обязан* скрыть порт Reality за Nginx (например, фаервол пропускает только 443), используй **TCP Stream Proxy**, а не HTTP/gRPC proxy:

```nginx
stream {
    map $ssl_preread_server_name $backend {
        www.amd.com      127.0.0.1:26009; # Порт Reality в Xray
        default          127.0.0.1:8443;  # Твой обычный сайт
    }

    server {
        listen 443;
        ssl_preread on;
        proxy_pass $backend;
        proxy_protocol on; # Опционально, если хочешь видеть реальный IP в Xray
    }
}
```
*Важно:* В этом случае в Reality Settings в 3x-ui нужно включить поддержку PROXY protocol (если включил `proxy_protocol on`), иначе Xray увидит IP nginx (127.0.0.1) и может забанить или некорректно работать. Но даже этот вариант хуже прямого подключения, так как добавляет задержку и точку отказа.

### ASSISTANT
Ты прав, я упустил контекст из файла. В нем описана настройка **XHTTP (SplitHTTP) + Reality** на порту `26009` в режиме `stream-one` с паддингом и кастомными заголовками, а не классический TCP+Vision.

Причина проблемы «подключение есть, интернета нет» при использовании Nginx перед этой конкретной конфигурацией:

**Nginx не поддерживает транспорт XHTTP (SplitHTTP) в режиме reverse proxy.**
XHTTP — это специфичный протокол поверх HTTP/2 или HTTP/3, который использует длинные POST-запросы и особую структуру потоков (`stream-one`). Стандартный `proxy_pass` в Nginx пытается буферизировать тело запроса или обрабатывать его как обычный REST API, что ломает бидирекциональный поток XHTTP. Соединение устанавливается (TLS-хендшейк проходит), но данные не передаются.

### Как пофиксить

У тебя два рабочих варианта, исходя из твоего конфига в файле:

#### Вариант 1: Прямой порт (Рекомендуемый для XHTTP)
XHTTP сам по себе маскируется под обычный HTTPS-трафик к сайту (благодаря `headers`, `path` и `xPaddingBytes`). Ему **не нужен** Nginx для защиты от сканеров.
1.  Оставь inbound `in-26009-xhttp` слушать напрямую на порту `26009`.
2.  Убедись, что Nginx **не** занимает этот порт и не проксирует его.
3.  В Happ подключайся напрямую на `IP:26009`.

#### Вариант 2: Если Nginx обязателен (например, фаервол пропускает только 443)
Используй **TCP Stream Proxy** (не HTTP!), чтобы прозрачно пробросить трафик в Xray без попыток его «понять»:

```nginx
stream {
    server {
        listen 443;
        proxy_pass 127.0.0.1:26009; # Порт твоего xhttp-inbound
        ssl_preread off;            # ВАЖНО: НЕ включать для xhttp! 
                                    # XHTTP сам внутри TLS, двойное чтение SNI сломает поток
    }
}
```

⚠️ **Критически важно:** Для XHTTP через stream-proxy нужно отключить `ssl_preread`. В отличие от Vision+TCP, где SNI читается на уровне TLS Record, XHTTP оборачивает данные иначе, и предварительное чтение SNI в Nginx может нарушить целостность пакета.

### Что проверить прямо сейчас
1.  Убедись, что в Happ выбран транспорт **XHTTP** (не TCP, не gRPC).
2.  Убедись, что `flow` пустой (в твоем конфиге `"flow": ""` — это правильно, Vision с XHTTP несовместим).
3.  Если используешь Nginx — проверь, что это именно блок `stream {}`, а не `http {}` с `proxy_pass`.

Если после исключения Nginx из цепочки интернет появляется — значит, проблема была именно в несовместимости XHTTP с HTTP-проксированием.

## Этап 6. Главный конфиг `/etc/nginx/nginx.conf`

```bash
cat <<'EOF' > /etc/nginx/nginx.conf
include /etc/nginx/modules-enabled/*.conf;

user www-data;
worker_processes auto;
events { worker_connections 1024; }

stream {
    include /etc/nginx/stream-map.conf;
    server {
        listen 443;
        listen [::]:443;
        proxy_pass $backend;
        ssl_preread on;
    }
}

http {
    include /etc/nginx/mime.types;
    default_type application/octet-stream;
    sendfile on;
    tcp_nopush on;
    keepalive_timeout 65;

    server_tokens off;
    autoindex off;

    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384:ECDHE-ECDSA-CHACHA20-POLY1305:ECDHE-RSA-CHACHA20-POLY1305;
    ssl_prefer_server_ciphers off;
    ssl_early_data off;
    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 1d;
    ssl_session_tickets off;

    ssl_stapling on;
    ssl_stapling_verify on;
    resolver 1.1.1.1 8.8.8.8 valid=300s;
    resolver_timeout 5s;

    add_header X-Content-Type-Options nosniff always;
    add_header Referrer-Policy strict-origin-when-cross-origin always;

    gzip on;
    gzip_vary on;
    gzip_proxied any;
    gzip_comp_level 5;
    gzip_min_length 256;
    gzip_types text/plain text/css text/xml text/javascript
               application/json application/javascript application/xml+rss
               application/xml image/svg+xml;

    log_format main '$remote_addr - $remote_user [$time_local] "$request" '
                     '$status $body_bytes_sent "$http_referer" '
                     '"$http_user_agent"';

    include /etc/nginx/sites-enabled/*.conf;
}
EOF
```

> Предупреждение `"ssl_stapling" ignored, no OCSP responder URL` при первой проверке — это норма, оно уйдёт после выпуска сертификата.

## Этап 4. Главный конфиг nginx.conf

Здесь мы разделяем `stream` (TCP-проксирование) и `http` (сайты). Для XHTTP+Reality в блоке stream **НЕЛЬЗЯ** использовать `ssl_preread on` в сервере по умолчанию.

```bash
cat <<'EOF' > /etc/nginx/nginx.conf
include /etc/nginx/modules-enabled/*.conf;

user www-data;
worker_processes auto;
events { worker_connections 1024; }

stream {
    include /etc/nginx/stream-map.conf;
    
    # Сервер для сайтов (читаем SNI)
    server {
        listen 443;
        listen [::]:443;
        proxy_pass $backend;
        ssl_preread on;
    }
}

http {
    include /etc/nginx/mime.types;
    default_type application/octet-stream;
    sendfile on;
    keepalive_timeout 65;
    server_tokens off;

    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384;
    ssl_prefer_server_ciphers off;
    ssl_session_cache shared:SSL:10m;
    ssl_session_timeout 1d;

    log_format main '$remote_addr - [$time_local] "$request" $status $body_bytes_sent';
    include /etc/nginx/sites-enabled/*.conf;
}
EOF
```

## Этап 5. Карта маршрутизации (stream-map.conf)

Сайты идут на 8080. Всё, что не совпало с сайтами (твой VLESS Reality), идёт на 8443.

```bash
cat <<'EOF' > /etc/nginx/stream-map.conf
map $ssl_preread_server_name $backend {
    away.norest.art      127.0.0.1:8080;
    ai.norest.art        127.0.0.1:8080;
    keygen.norest.art    127.0.0.1:8080;
    default              127.0.0.1:8443;
}
EOF
```

> **Важно:** Когда клиент подключается к Reality, он шлёт SNI `www.amd.com`. В карте нет такого имени, поэтому срабатывает `default` → `8443`. Трафик передается в Xray «как есть», без попыток его расшифровать.

# Полный гайд: Ubuntu → VLESS+XHTTP+Reality (рабочая связка через nginx L4-stream)

# ЭТАП 1. Сервер без сертификатов — база

## 1.1 Подготовка системы

```bash
apt update && apt upgrade -y && apt install -y curl wget sudo ufw socat cron unzip && timedatectl set-timezone UTC && lsb_release -a
```

## 1.2 Firewall — минимум для старта

```bash
ufw allow 22/tcp && ufw allow 8443/tcp && ufw allow 2053/tcp && ufw enable && ufw status numbered
```

- `22` — SSH, не трогай, иначе отрубишь себе доступ
- `8443` — сюда будет стучаться Happ (это твой рабочий порт из логов)
- `2053` — временно панель 3x-ui, дальше сузим до своего IP

Порт `26009` (внутренний xray) в ufw **не открываем никогда** — он живёт только на `127.0.0.1`.

## 1.3 Установка nginx

```bash
apt install -y nginx && systemctl enable nginx && systemctl status nginx --no-pager
```

## 1.4 nginx.conf — добавляем stream-блок

```bash
grep -nE "stream \{" /etc/nginx/nginx.conf
```

Если пусто — открываем:

```bash
nano /etc/nginx/nginx.conf
```

В конец файла, **на уровне** блока `http{}` (не внутри него), добавляем:

```nginx
stream {
    include /etc/nginx/conf.d/stream-*.conf;
}
```

Сохраняем: `Ctrl+O` → `Enter` → `Ctrl+X`.

## 1.5 Сам stream-конфиг — твой рабочий фикс

Это именно та конфигурация, которая у тебя реально заработала (проверено tcpdump-диагностикой в прошлой сессии):

```bash
cat > /etc/nginx/conf.d/stream-reality.conf << 'EOF'
server {
    listen 8443;
    proxy_pass 127.0.0.1:26009;
    proxy_protocol off;
    ssl_preread off;
}
EOF
```

Почему именно так:
- `listen 8443` — порт, на который стучится Happ снаружи
- `proxy_pass 127.0.0.1:26009` — реальный порт XHTTP-инбаунда в 3x-ui
- `proxy_protocol off` — обязательно, XHTTP не понимает PROXY protocol заголовки
- `ssl_preread off` — ключевой момент: XHTTP уже сам несёт TLS/HTTP-обёртку внутри себя, если включить `ssl_preread`, nginx попытается парсить SNI из ClientHello и сломает поток на XHTTP-фреймах (это и было причиной "0 packets" в прошлой диагностике — старая версия конфига с `ssl_preread on` из другого твоего гайда для SNI-роутинга сюда не подходит, это разные архитектуры)

Проверка и применение:

```bash
nginx -t && systemctl reload nginx
```

# ЭТАП 7. Диагностика проблем

```bash

```

- **tcpdump показывает "0 packets captured" при "N received by filter"** — это баг буферизации вывода, не реальное отсутствие трафика. Используй именно `timeout 30 tcpdump ... -c 20 > file.txt 2>&1`, как в Этапе 4 — так надёжнее, без ручного `Ctrl+C` и фоновых джобов.

- **Проверь fail2ban**, если подключение то есть то нет — мобильные операторы часто сидят на CGNAT, один и тот же диапазон могли забанить за чужую активность:

### ASSISTANT
Ошибка `"proxy_pass" directive is not allowed here` означает, что файл `stream-reality.conf` снова попал внутрь блока `http {}`, а не `stream {}`. Это происходит потому, что в `nginx.conf` есть строка `include /etc/nginx/conf.d/*.conf;` внутри блока `http`, и она подхватывает все файлы из этой папки.

Нужно переместить stream-конфиг в отдельную директорию, которую include'ит только блок `stream`.

Выполни всё одной командой:

```bash
mkdir -p /etc/nginx/stream-conf.d && mv /etc/nginx/conf.d/stream-reality.conf /etc/nginx/stream-conf.d/ && sed -i 's|include /etc/nginx/conf.d/stream-\*\.conf;|include /etc/nginx/stream-conf.d/*.conf;|g' /etc/nginx/nginx.conf && nginx -t && systemctl reload nginx && ss -tlnp | grep -E ':8443|:26009'
```

Эта команда:
1. Создаёт изолированную папку `/etc/nginx/stream-conf.d/`
2. Переносит туда `stream-reality.conf` (убирая из `conf.d/`)
3. Обновляет путь в `nginx.conf` внутри блока `stream {}`
4. Проверяет и перезапускает nginx
5. Показывает, что порты 8443 и 26009 слушаются

Если после этого `nginx -t` проходит — подключайся через Happ на порт **8443** с SNI `www.amd.com`.

### 1.2 Изолированная структура для stream-блока
Создаём отдельную папку для stream-конфигов, чтобы они **никогда** не попадали в блок `http {}`:
```bash
mkdir -p /etc/nginx/stream-conf.d /var/www/certbot /etc/nginx/sites-available /etc/nginx/sites-enabled
```

### 1.3 Чистый nginx.conf
Перезаписываем полностью, чтобы исключить дублирующиеся/неверные include:
```bash
cat <<'EOF' > /etc/nginx/nginx.conf
include /etc/nginx/modules-enabled/*.conf;

user www-data;
worker_processes auto;
events { worker_connections 1024; }

stream {
    include /etc/nginx/stream-conf.d/*.conf;
}

http {
    include /etc/nginx/mime.types;
    default_type application/octet-stream;
    sendfile on; keepalive_timeout 65; server_tokens off;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384;
    ssl_prefer_server_ciphers off; ssl_session_cache shared:SSL:10m; ssl_session_timeout 1d;
    log_format main '$remote_addr - [$time_local] "$request" $status $body_bytes_sent';
    include /etc/nginx/conf.d/*.conf;
    include /etc/nginx/sites-enabled/*.conf;
}
EOF
```

### 1.4 Stream-конфиг (рабочая схема без ssl_preread)
Файл лежит в `stream-conf.d/`, а не в `conf.d/` — поэтому Nginx включает его **только** в блок `stream {}`:
```bash
cat <<'EOF' > /etc/nginx/stream-conf.d/stream-reality.conf
server {
    listen 8443;
    proxy_pass 127.0.0.1:26009;
    proxy_protocol off;
    ssl_preread off;
}
EOF
nginx -t && systemctl reload nginx && ss -tlnp | grep :8443
```
Должно показать `nginx` на порту `8443`. Если ошибка — не продолжай, пока не починишь.

### ASSISTANT
Ошибка `unknown directive "stream"` означает, что в твоей сборке nginx **не загружен модуль stream**. В Ubuntu/Debian пакет `nginx-full` обычно включает его, но иногда модуль лежит в `/etc/nginx/modules-enabled/` и не подтягивается автоматически, либо установлен `nginx-core` без stream.

Нужно убедиться, что модуль подключён, и только потом использовать директиву `stream`.

Выполни диагностику и фикс одной командой:
```bash
ls /etc/nginx/modules-enabled/ | grep stream || (apt install -y nginx-extras && ln -sf /usr/share/nginx/modules-available/mod-stream.conf /etc/nginx/modules-enabled/50-mod-stream.conf) && nginx -t
```

Если после этого `nginx -t` проходит — можно применять гайд. Если нет — покажи вывод `nginx -V 2>&1 | grep stream` и `ls /etc/nginx/modules-enabled/`.

## ЭТАП 3. Inbound XHTTP+Reality (stream-one + padding obfs + headers)

Конфиг основан на твоём рабочем варианте из `процесс.txt`. Ключевые особенности:
- `mode: "stream-one"` — единый HTTP-поток, маскировка под загрузку файла/страницы

- `xPaddingBytes: "150-1200"` — padding obfs, сбивает распознавание по размеру пакетов
- Реалистичные заголовки под amd.com CDN (Referer, Origin, Accept-Language, X-Requested-With)
- `noGRPCHeader: true` — gRPC-заголовки противоречат браузерному профилю
- `fingerprint: chrome` — массовый ClientHello профиль

### 3.1 Импорт конфига
В панели: **Inbounds → Import**. Вставь этот JSON:


# Полный гайд: VLESS+XHTTP+Reality + панель 3x-ui на домене away.norest.art

## ЭТАП 1. Система, firewall, nginx со stream-модулем

### 1.1 Установка и открытие портов
```bash
apt update && apt upgrade -y && apt install -y curl wget sudo ufw socat cron unzip nginx certbot && timedatectl set-timezone UTC && ufw allow 22/tcp && ufw allow 80/tcp && ufw allow 443/tcp && ufw allow 8443/tcp && ufw allow 30000/tcp && ufw --force enable && systemctl enable nginx && systemctl start nginx
```
Порты:
- `22` — SSH
- `80/443` — сертификаты и панель по домену
- `8443` — внешний порт VPN (Happ стучится сюда)
- `30000` — панель 3x-ui (временный прямой доступ, закроем позже)
- Порт `26009` (внутренний xray) наружу **не открываем никогда**

### 1.2 Проверка и подключение stream-модуля
Без этого модуля директива `stream` в nginx.conf вызовет ошибку `unknown directive`:
```bash
ls /etc/nginx/modules-enabled/ | grep -q stream || (apt install -y nginx-extras && ln -sf /usr/share/nginx/modules-available/mod-stream.conf /etc/nginx/modules-enabled/50-mod-stream.conf) && nginx -t
```
Если `nginx -t` падает после этого — выполни `nginx -V 2>&1 | grep stream` и `ls /etc/nginx/modules-enabled/` для диагностики. Без рабочего stream-модуля дальше идти нельзя.

### 1.3 Создание изолированной структуры
Stream-конфиги кладём в отдельную папку, чтобы nginx не пытался парсить их как HTTP (это была причина ошибки `proxy_pass directive is not allowed here`):
```bash
mkdir -p /etc/nginx/stream-conf.d /var/www/certbot /etc/nginx/sites-available /etc/nginx/sites-enabled
```

### 1.4 Чистый nginx.conf
Перезаписываем полностью, чтобы исключить конфликты include'ов:
```bash
cat <<'EOF' > /etc/nginx/nginx.conf
include /etc/nginx/modules-enabled/*.conf;

user www-data;
worker_processes auto;
events { worker_connections 1024; }

stream {
    include /etc/nginx/stream-conf.d/*.conf;
}

http {
    include /etc/nginx/mime.types;
    default_type application/octet-stream;
    sendfile on; keepalive_timeout 65; server_tokens off;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384;
    ssl_prefer_server_ciphers off; ssl_session_cache shared:SSL:10m; ssl_session_timeout 1d;
    log_format main '$remote_addr - [$time_local] "$request" $status $body_bytes_sent';
    include /etc/nginx/conf.d/*.conf;
    include /etc/nginx/sites-enabled/*.conf;
}
EOF
```

### 1.5 Stream-конфиг для VPN (без ssl_preread)
Nginx прозрачно проксирует TCP-поток с 8443 на 26009 без попыток читать TLS/SNI. XHTTP уже несёт свою обёртку внутри, двойное чтение ломает поток:
```bash
cat <<'EOF' > /etc/nginx/stream-conf.d/stream-reality.conf
server {
    listen 8443;
    proxy_pass 127.0.0.1:26009;
    proxy_protocol off;
    ssl_preread off;
}
EOF
nginx -t && systemctl reload nginx && ss -tlnp | grep :8443
```
Должно показать `nginx` на порту `8443`. Если нет — не продолжай.

### ASSISTANT
Ошибка `use of closed network connection` в логах Xray при работе через Nginx Stream Proxy — это **не проблема конфига inbound**, а следствие того, что Nginx закрывает TCP-соединение раньше, чем Xray успевает его обработать.

Причина: в твоем stream-конфиге **не указан таймаут**. По умолчанию Nginx использует очень короткий таймаут для stream-прокси, и для XHTTP `stream-one` (который держит длинное соединение) этого недостаточно. Соединение устанавливается, но Nginx рвёт его до завершения handshake с Xray.

### Фикс одной командой

Добавляем `proxy_timeout` и `proxy_connect_timeout` в stream-конфиг:

```bash
cat <<'EOF' > /etc/nginx/stream-conf.d/stream-reality.conf
server {
    listen 8443;
    proxy_pass 127.0.0.1:26009;
    proxy_protocol off;
    ssl_preread off;
    proxy_timeout 1h;
    proxy_connect_timeout 60s;
}
EOF
nginx -t && systemctl reload nginx
```

После этого перезапусти x-ui, чтобы сбросить зависшие соединения:
```bash
systemctl restart x-ui && journalctl -u x-ui -f --no-hostname -n 30
```

Подключись через Happ. Ошибка `use of closed network connection` должна исчезнуть.

### Почему это произошло

XHTTP `stream-one` — это **длинное HTTP-соединение** (похоже на SSE или WebSocket). Без явного `proxy_timeout` Nginx применяет дефолтный таймаут (обычно 10 минут для stream, но в некоторых сборках меньше), и при первом же паузе в передаче данных или при медленном handshake рвёт соединение. Для VPN-трафика нужен таймаут минимум 1 час.

### Обновление в гайде

В **Этапе 1.5** гайда замени содержимое stream-конфига на версию с таймаутами:

```bash
cat <<'EOF' > /etc/nginx/stream-conf.d/stream-reality.conf
server {
    listen 8443;
    proxy_pass 127.0.0.1:26009;
    proxy_protocol off;
    ssl_preread off;
    proxy_timeout 1h;
    proxy_connect_timeout 60s;
}
EOF
```

Это обязательное дополнение для работы XHTTP `stream-one` через Nginx L4-proxy. Без таймаутов соединение будет рваться.

## ЭТАП 1. Система, firewall, nginx со stream-модулем

### 1.1 Установка и открытие портов

### 1.2 Проверка и подключение stream-модуля
Без этого модуля директива `stream` в nginx.conf вызовет ошибку `unknown directive`:
```bash
ls /etc/nginx/modules-enabled/ | grep -q stream || (apt install -y nginx-extras && ln -sf /usr/share/nginx/modules-available/mod-stream.conf /etc/nginx/modules-enabled/50-mod-stream.conf) && nginx -t
```

### 1.3 Создание изолированной структуры
Stream-конфиги кладём в отдельную папку, чтобы nginx не пытался парсить их как HTTP (это была причина ошибки `proxy_pass directive is not allowed here`):
```bash
mkdir -p /etc/nginx/stream-conf.d /var/www/certbot /etc/nginx/sites-available /etc/nginx/sites-enabled
```

### 1.4 Чистый nginx.conf
Перезаписываем полностью, чтобы исключить конфликты include'ов:
```bash
cat <<'EOF' > /etc/nginx/nginx.conf
include /etc/nginx/modules-enabled/*.conf;

user www-data;
worker_processes auto;
events { worker_connections 1024; }

stream {
    include /etc/nginx/stream-conf.d/*.conf;
}

http {
    include /etc/nginx/mime.types;
    default_type application/octet-stream;
    sendfile on; keepalive_timeout 65; server_tokens off;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384;
    ssl_prefer_server_ciphers off; ssl_session_cache shared:SSL:10m; ssl_session_timeout 1d;
    log_format main '$remote_addr - [$time_local] "$request" $status $body_bytes_sent';
    include /etc/nginx/conf.d/*.conf;
    include /etc/nginx/sites-enabled/*.conf;
}
EOF
```

### 1.5 Stream-конфиг для VPN (без ssl_preread + с таймаутами)
Nginx прозрачно проксирует TCP-поток с 8443 на 26009 без попыток читать TLS/SNI. **Таймауты обязательны** для XHTTP `stream-one` — без них Nginx рвёт длинное соединение раньше, чем Xray успевает его обработать (ошибка `use of closed network connection`):

```bash
    ssl_preread off;
```

Должно показать `nginx` на порту `8443`. Если нет — не продолжай.

## ЭТАП 3. Inbound XHTTP+Reality (stream-one + padding obfs + headers)

Конфиг основан на твоём рабочем варианте из `процесс.txt`. Ключевые особенности:
- `mode: "stream-one"` — единый HTTP-поток, маскировка под загрузку файла/страницы
- `flow: ""` — Vision несовместим с xhttp, это архитектурное ограничение протокола
- `xPaddingBytes: "150-1200"` — padding obfs, сбивает распознавание по размеру пакетов
- Реалистичные заголовки под amd.com CDN (Referer, Origin, Accept-Language, X-Requested-With)
- `noGRPCHeader: true` — gRPC-заголовки противоречат браузерному профилю при stream-one
- `fingerprint: chrome` — массовый ClientHello профиль, меньше выделяется в трафике
- `xmux` с рандомизированными диапазонами — чтобы TLS/H2-профиль не был статичным «отпечатком»

### 3.1 Импорт конфига
В панели: **Inbounds → Import**. Вставь этот JSON:


# Полный гайд: VLESS+XHTTP+Reality + панель 3x-ui на домене away.norest.art

## ЭТАП 1. Система, firewall, nginx со stream-модулем

### 1.1 Установка и открытие портов
```bash
apt update && apt upgrade -y && apt install -y curl wget sudo ufw socat cron unzip nginx certbot && timedatectl set-timezone UTC && ufw allow 22/tcp && ufw allow 80/tcp && ufw allow 443/tcp && ufw allow 8443/tcp && ufw allow 30000/tcp && ufw --force enable && systemctl enable nginx && systemctl start nginx
```
Порты:
- `22` — SSH
- `80/443` — сертификаты и панель по домену
- `8443` — внешний порт VPN (Happ стучится сюда)
- `30000` — панель 3x-ui (временный прямой доступ, закроем на Этапе 5.6)
- Порт `2096` (подписки) наружу **не открываем никогда** — доступ только через nginx reverse proxy
- Порт `26009` (внутренний xray) наружу **не открываем никогда**

### 1.2 Проверка и подключение stream-модуля
```bash
ls /etc/nginx/modules-enabled/ | grep -q stream || (apt install -y nginx-extras && ln -sf /usr/share/nginx/modules-available/mod-stream.conf /etc/nginx/modules-enabled/50-mod-stream.conf) && nginx -t
```
Если `nginx -t` падает — выполни `nginx -V 2>&1 | grep stream` и `ls /etc/nginx/modules-enabled/`. Без stream-модуля дальше идти нельзя.

### 1.3 Создание изолированной структуры
```bash
mkdir -p /etc/nginx/stream-conf.d /var/www/certbot /etc/nginx/sites-available /etc/nginx/sites-enabled
```

### 1.4 Чистый nginx.conf
```bash
cat <<'EOF' > /etc/nginx/nginx.conf
include /etc/nginx/modules-enabled/*.conf;

user www-data;
worker_processes auto;
events { worker_connections 1024; }

stream {
    include /etc/nginx/stream-conf.d/*.conf;
}

http {
    include /etc/nginx/mime.types;
    default_type application/octet-stream;
    sendfile on; keepalive_timeout 65; server_tokens off;
    ssl_protocols TLSv1.2 TLSv1.3;
    ssl_ciphers ECDHE-ECDSA-AES128-GCM-SHA256:ECDHE-RSA-AES128-GCM-SHA256:ECDHE-ECDSA-AES256-GCM-SHA384:ECDHE-RSA-AES256-GCM-SHA384;
    ssl_prefer_server_ciphers off; ssl_session_cache shared:SSL:10m; ssl_session_timeout 1d;
    log_format main '$remote_addr - [$time_local] "$request" $status $body_bytes_sent';
    include /etc/nginx/conf.d/*.conf;
    include /etc/nginx/sites-enabled/*.conf;
}
EOF
```

### 1.5 Stream-конфиг для VPN (без ssl_preread + с таймаутами)
Таймауты обязательны для XHTTP `stream-one` — без них Nginx рвёт длинное соединение (ошибка `use of closed network connection`):
```bash
cat <<'EOF' > /etc/nginx/stream-conf.d/stream-reality.conf
server {
    listen 8443;
    proxy_pass 127.0.0.1:26009;
    proxy_protocol off;
    ssl_preread off;
    proxy_timeout 1h;
    proxy_connect_timeout 60s;
}
EOF
nginx -t && systemctl reload nginx && ss -tlnp | grep :8443
```
Должно показать `nginx` на `8443`. Если нет — не продолжай.
